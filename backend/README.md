# Farmer Procurement Management System - Backend API

Production-ready backend API service built with Node.js, Express, and PostgreSQL database persistence for the Farmer Procurement Management Platform.

## 2. Notification Architecture Audit

The system features a **3-Tier Notification Delivery Architecture**:

| Tier | Type | Implementation | Description |
| :--- | :--- | :--- | :--- |
| **Tier 1** | **Database Notifications** | PostgreSQL `notifications` table | Persistent audit trail of all notifications generated by queue events, token issuances, and weighment approvals. Queryable via `GET /api/v1/farmers/:id/notifications`. |
| **Tier 2** | **Local Android Notifications** | `flutter_local_notifications` plugin | High-priority local device alerts (sound + vibration) triggered instantly when farmer turn approaches or queue advances. Works seamlessly without third-party push dependencies. |
| **Tier 3** | **Remote Push Notifications** | Prepared FCM Architecture | Device token registration endpoint (`POST /api/v1/farmers/device-token`) ready for Firebase Cloud Messaging (FCM) server key payload dispatch. |

## 3. Environment Configuration

Create a `.env` file inside the `backend/` directory or export environment variables:

```env
# Application Port & Node Environment
PORT=3000
NODE_ENV=production

# API Gateway URL
API_BASE_URL=https://farmer-procurement-app-i0g6.onrender.com/api/v1

# Security & CORS
JWT_SECRET=prod_super_secret_jwt_key_9847192837
CORS_ORIGIN=*

# PostgreSQL Database Connection String
DATABASE_URL=postgresql://procurement_user:secure_password@localhost:5432/farmer_procurement

# SMS Provider Adapter Configuration (TWILIO / FAST2SMS / DEV)
SMS_PROVIDER=DEV
TWILIO_ACCOUNT_SID=
TWILIO_AUTH_TOKEN=
TWILIO_PHONE_NUMBER=
FAST2SMS_API_KEY=

# Government API & Maps Integrations
GOVERNMENT_API_BASE_URL=
GOVERNMENT_API_KEY=
MAPS_API_KEY=
```

> **IMPORTANT**: In production (`NODE_ENV=production`), the application will refuse to start if `JWT_SECRET` is unset or left as the default placeholder.

## 4. API Endpoint Directory

### Authentication Endpoints
- `POST /api/v1/auth/otp/send`: Request 6-digit SMS OTP for farmer login.
- `POST /api/v1/auth/otp/verify`: Verify SMS OTP & issue JWT session token.
- `POST /api/v1/auth/farmer/login`: Single-step mobile authentication.
- `POST /api/v1/auth/officer/login`: Procurement officer badge login.

### Procurement & Queue Endpoints
- `GET /api/v1/procurement/centres`: List all registered procurement centres with live status and GPS coordinates.
- `GET /api/v1/procurement/centres/:id`: Retrieve single procurement centre details.
- `GET /api/v1/farmers/:id/token`: Fetch active token status for farmer.
- `GET /api/v1/farmers/:id/queue`: Retrieve live queue sequence, serving token, and estimated wait times.
- `POST /api/v1/farmers/token/book`: Book new paddy procurement slot & issue token.

### Officer Controls
- `POST /api/v1/officer/queue/call-next`: Advance queue to next token and issue automated farmer notifications.
- `POST /api/v1/officer/procurement/update`: Progress token through weighment, moisture test, and warehouse acceptance.
- `POST /api/v1/officer/centre/status`: Update centre operational status (OPEN / BUSY / PAUSED / CLOSED).

### Financial & Grievance Endpoints
- `GET /api/v1/farmers/:id/payments`: Retrieve MSP payout history and PFMS DBT reference numbers.
- `GET /api/v1/farmers/:id/notifications`: List all farmer notifications.
- `POST /api/v1/grievances`: File farmer grievance for moisture calibration or queue issues.
- `GET /api/v1/grievances`: Fetch grievances for officer review.

### Health Check
- `GET /api/v1/health`: System health monitor reporting Express and PostgreSQL connectivity status.

## 5. Database Setup & Migrations

### Run Database Migration (Schema Setup)
Executes DDL to create all 12 relational entity tables (`users`, `farmers`, `officers`, `procurement_centres`, `tokens`, `queue_entries`, `procurement_records`, `payments`, `notifications`, `grievances`, `documents`, `audit_logs`) along with indexes and constraints:

```bash
npm run db:migrate
```

### Seed Development Data (Development ONLY)
Populates realistic sample data for local testing.

```bash
npm run db:seed
```
